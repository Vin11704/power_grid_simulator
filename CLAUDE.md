1. When editing code, do not delete code, instead comment them out.
2. Do Not Repeat Yourself. Adhere to the DRY principle
3. When looking for bugs, pinpoint the core issue first before refactoring code
4. IMPORTANT: Use a TDD approach to solving problems. *Do not assume* that your solution is correct. Instead, *validate your solution is correct* by first creating a test case and running the test case to _prove_ the solution is working as intended.
5. Assume your world knowledge is out of date. Use your web search tool to find up-to-date docs and information.
6. **KISS (Keep It Simple, Stupid)**: Strive for simplicity in design and implementation. Avoid over-engineering.
